## Как обновлять сайт после `pnpm build`

Прод-сборка деплоится вручную (не автоматически при пуше):

```bash
pnpm exec vite build --base=/chistaya-rech/   # ВАЖНО: без --base пути сломаются на Pages
npx gh-pages -d dist
```

В git-bash на этой машине флаг `--base=/...` иногда коверкается MSYS-конвертацией путей —
если в `dist/index.html` пути к ассетам выглядят как `/Programm's/Git/...` вместо
`/chistaya-rech/...`, добавить `MSYS_NO_PATHCONV=1 MSYS2_ARG_CONV_EXCL="*"` перед командой.

## Диагностика: dev-сервер недоступен локально (решено 2026-09-22)

**Три релиза подряд (обновление палитры, отзывы, точечные правки) деплоились "вслепую"** —
ни `curl`/`Test-NetConnection` из git-bash/PowerShell, ни браузер Playwright не могли
подключиться к `pnpm dev`, хотя `netstat`/`Get-NetTCPConnection` показывали порт в состоянии
`Listen` с живым процессом `node.exe`. Причина найдена и исправлена:

- **Корень проблемы**: Vite по умолчанию биндится ТОЛЬКО на IPv6-loopback (`::1`), не на все
  интерфейсы. Проверено через `Get-NetTCPConnection` — `LocalAddress` был именно `::1`, а не
  `::`/`0.0.0.0`. Обычный `node -e "http.createServer(...).listen(PORT)"` (без явного host)
  биндится на `::` (все интерфейсы) и был доступен всегда, даже когда Vite — нет.
- **Почему это ломает именно `::1`, а не мешает `::`**: на этой машине есть несколько
  виртуальных сетевых адаптеров (VPN/туннели — в выводе `pnpm dev --host` видны `wg0`,
  `happ-tun`, Tailscale-подобный адрес и Hyper-V `vEthernet`). Судя по всему, сетевой путь,
  через который локальные инструменты/агенты (в т.ч. Claude Code) обращаются к `localhost`,
  идёт не через "настоящий" единственный IPv6-loopback хоста, а через один из этих
  туннелей/адаптеров — такой путь, похоже, форвардится только до сокетов, слушающих на "всех
  интерфейсах", но не до сокетов, забинденных строго на `::1`.
- **Это НЕ было связано с папкой проекта** — гипотеза "может, дело в том, что раньше работали
  из `Klich`, а теперь из `chistaya-rech`" была логичной (в `Klich` через Playwright открыть
  сайт получалось), но проверка её не подтвердила: тестовый `node`-сервер, поднятый прямо из
  `chistaya-rech`, точно так же был доступен, как и такой же сервер из `Klich`. Дело было
  именно в том, что конкретно Vite биндится на loopback-only, а не в рабочей папке.
- **Исправлено в `vite.config.ts`**: добавлено `server: { host: true }` — теперь `pnpm dev`
  без каких-либо флагов слушает все интерфейсы (эквивалент `vite --host`) и открывается и
  локально в браузере, и через инструменты в сессии Claude Code. Проверено: `curl`/Playwright
  успешно подключились. **Если в будущем снова возникнет `ERR_CONNECTION_REFUSED`/`actively
  refused` при живом `Listen`-порте** — первым делом проверить `Get-NetTCPConnection`, на каком
  именно `LocalAddress` слушает процесс (если `::1` — значит `server.host` в конфиге где-то
  потерялся/переопределился).
- Ретроспективно посмотрели на живом `pnpm dev` (после фикса) все три "слепых" релиза —
  визуально всё соответствует ожиданиям: новая палитра, кнопка "Показать ещё отзывы"
  разворачивает все 14 отзывов, "Диагностика — бесплатно" оранжевая, тариф "16 занятий" не
  выделяется, возраст "от 4 лет" без верхней границы. Проблем не найдено.

## Переключатель версии сайта (мобильная / десктопная)

`src/hooks/useViewMode.ts` + `src/components/ViewModeToggle.tsx` (кнопки в футере), выбор
хранится в `localStorage` (`chistaya-rech-view-mode`) и применяется сразу при загрузке
инлайн-скриптом в `index.html` (чтобы не было мигания).

Механизм асимметричный — так как десктопные браузеры игнорируют `<meta viewport>`,
а мобильные браузеры не позволяют скриптом эмулировать другую реальную ширину окна:

- **"Компьютер"** (`desktop`): меняет `<meta name="viewport">` на `width=1280`. Работает только
  на мобильных браузерах (они реально используют этот layout viewport для медиазапросов) —
  реальные `lg:`-классы Tailwind срабатывают сами, без доп. переопределений. На десктопе — no-op
  (браузер и так уже desktop).
- **"Телефон"** (`mobile`): ставит `data-view="mobile"` на `<html>`. В `src/index.css` определён
  кастомный Tailwind-вариант `force-mobile` (`@custom-variant force-mobile`), который бьёт по
  `!important` поверх реальных `lg:`-классов независимо от фактической ширины окна — иначе
  повлиять на десктопный браузер, игнорирующий viewport meta, никак нельзя.
  **Важно:** при добавлении новой секции с `lg:grid-cols-*` / `lg:flex` / `lg:order-*` и т.п. —
  нужно продублировать соответствующим `force-mobile:...!` классом, иначе новая секция не
  свернётся в мобильный вид при принудительном "Телефон"-режиме на широком окне.
- **"Авто"** — сбрасывает всё, обычное адаптивное поведение по реальной ширине окна.

Проверено вручную через Playwright: на реальном desktop-окне (1440px) режим "Телефон"
корректно сворачивает всю страницу в мобильную раскладку (бургер-меню, одна колонка везде).
Режим "Компьютер" на реальном узком окне не удалось визуально проверить в тестовом браузере
(Playwright/Chromium — десктопный движок, он тоже игнорирует viewport meta, в отличие от
настоящих мобильных браузеров) — проверена только корректность JS-логики (атрибут и meta
проставляются верно). Стоит перепроверить на реальном телефоне при случае.
