# Чистая речь — контекст для Claude Code

Сайт-одностраничник для онлайн-занятий с учителем-логопедом Анастасией. Первый шаг перед
будущей кроссплатформенной развивающей игровой платформой с логопедическими играми.

- **Этот файл — рабочий журнал.** Обновляй секцию "Текущее состояние" и таблицу прогресса
  после каждого значимого этапа, как в `D:\Projects\Klich\CLAUDE.md`.

## Брендбук — источник истины для дизайна

Файлы брендбука лежат в `assets-source/brand-v2/`:
`Brendbuk_Anastasia_logoped_1.pdf`, `colors.png`, `shrift.jpg`, `logo3.png`.
**Любые дизайн-решения (цвета, шрифты, тон текста, стиль иллюстраций) должны сверяться
с этим брендбуком**, а не придумываться заново.

### Типографика

- Заголовки — **Nunito** Bold/ExtraBold, обычный регистр (не капс) → `.font-heading`
- Основной текст — **Montserrat** Regular/Medium, 14–16pt → шрифт по умолчанию (`body`)
- Рукописные акценты/цитаты — **Caveat**, дозированно, 1–2 фразы на странице → `.font-accent`

### Тон общения

Тепло, спокойно, уверенно, простым языком, без запугивания и давления, с уважением
к ребёнку и родителю. Пример одобренной фразы (уже используется в блоке "Обо мне"):
«Играя, мы мягко ставим звук [р] — ребёнок даже не замечает, что это занятие».

### Логотип

`src/assets/logo.png` — обработан из `assets-source/brand-v2/logo3.png` скриптом
`scripts/remove-logo-bg.py` (снятие белого фона, ресайз до 640px). Не менять цвета логотипа,
оставлять свободное поле вокруг (минимум высота буквы «А»), минимальный размер в вебе — 100px
по ширине (в шапке используется 56–64px как практичный компромисс для инлайн-лого рядом
с текстом).

### Аудитория и позиционирование

Дети от 4 до 10 лет (не от 3 — поправлено по брендбуку). Позиционирование: современный,
дружелюбный специалист, которому доверяют — мягко, но профессионально.

## Как обновлять сайт после `pnpm build`

Прод-сборка деплоится вручную (не автоматически при пуше):

```bash
pnpm exec vite build --base=/chistaya-rech/   # ВАЖНО: без --base пути сломаются на Pages
npx gh-pages -d dist
```

В git-bash на этой машине флаг `--base=/...` иногда коверкается MSYS-конвертацией путей —
если в `dist/index.html` пути к ассетам выглядят как `/Programm's/Git/...` вместо
`/chistaya-rech/...`, добавить `MSYS_NO_PATHCONV=1 MSYS2_ARG_CONV_EXCL="*"` перед командой.

## Переключатель версии сайта (мобильная / десктопная)

`src/hooks/useViewMode.ts` + `src/components/ViewModeToggle.tsx` (кнопки в футере), выбор
хранится в `localStorage` (`chistaya-rech-view-mode`) и применяется сразу при загрузке
инлайн-скриптом в `index.html` (чтобы не было мигания).

Механизм асимметричный — так как десктопные браузеры игнорируют `<meta viewport>`,
а мобильные браузеры не позволяют скриптом эмулировать другую реальную ширину окна:

- **"Компьютер"** (`desktop`): меняет `<meta name="viewport">` на `width=1280`. Работает только
  на мобильных браузерах (они реально используют этот layout viewport для медиазапросов) —
  реальные `lg:`-классы Tailwind срабатывают сами, без доп. переопределений. На десктопе — no-op
  (браузер и так уже desktop).
- **"Телефон"** (`mobile`): ставит `data-view="mobile"` на `<html>`. В `src/index.css` определён
  кастомный Tailwind-вариант `force-mobile` (`@custom-variant force-mobile`), который бьёт по
  `!important` поверх реальных `lg:`-классов независимо от фактической ширины окна — иначе
  повлиять на десктопный браузер, игнорирующий viewport meta, никак нельзя.
  **Важно:** при добавлении новой секции с `lg:grid-cols-*` / `lg:flex` / `lg:order-*` и т.п. —
  нужно продублировать соответствующим `force-mobile:...!` классом, иначе новая секция не
  свернётся в мобильный вид при принудительном "Телефон"-режиме на широком окне.
- **"Авто"** — сбрасывает всё, обычное адаптивное поведение по реальной ширине окна.

Проверено вручную через Playwright: на реальном desktop-окне (1440px) режим "Телефон"
корректно сворачивает всю страницу в мобильную раскладку (бургер-меню, одна колонка везде).
Режим "Компьютер" на реальном узком окне не удалось визуально проверить в тестовом браузере
(Playwright/Chromium — десктопный движок, он тоже игнорирует viewport meta, в отличие от
настоящих мобильных браузеров) — проверена только корректность JS-логики (атрибут и meta
проставляются верно). Стоит перепроверить на реальном телефоне при случае.

## Реальный контент v1 (от заказчика)

`assets-source/content-v1/` — присланный заказчиком пакет: `Заголовок (5).png` (широкий баннер
6000×2400 с реальным фото Анастасии, логотипом и текстом заголовка, уже вёрстанный как готовая
графика) + 6 иконок разделов в фирменном flat-стиле (`О СЕБЕ`, `УСЛУГИ`, `ЗАПИСЬ`, `КОНТАКТЫ`,
`МАТЕРИАЛЫ`, `ОТЗЫВЫ`).

- **Баннер используется целиком, без обрезки** — как единая картинка в `Hero.tsx`
  (`src/assets/hero-banner.jpg`, пережат с 6000×2400/14 МБ до 2200×880/~200 КБ, `quality=85`).
  Первая версия ошибочно вырезала из него только фото Анастасии и разносила фото+текст на
  отдельные HTML-элементы — пользователь явно попросил это отменить: баннер задуман и прислан
  как цельная графика для шапки (Hero), не сырьё для нарезки. `<h1>` рядом с картинкой — `sr-only`
  (для доступности/SEO, картинка не даёт этого сама).
  **Известное ограничение:** это широкий (2.5:1) баннер с текстом, вшитым в пиксели — на узких
  экранах (мобильный) он пропорционально уменьшается вместе с текстом, который может читаться
  мелко. Не переделывать в адаптивный вариант без отдельной просьбы — баннер временный, заказчик
  планирует отдельную профессиональную фотосессию позже.
- **В "Обо мне" фото не используем** — по просьбе пользователя, там намеренно остаётся плейсхолдер
  (`Фото Анастасии`) до отдельной фотографии в будущем. Не вставлять сюда фото из баннера снова.
- Иконки скопированы в `src/assets/icons/` (обрезаны по центру в квадрат, сжаты до 220px webp):
  `about.webp`, `services.webp`, `booking.webp`, `contacts.webp`, `materials.webp`,
  `testimonials.webp`. Расставлены рядом с заголовками секций (About/Services/Testimonials/
  Contacts) и на карточках шагов 1 и 4 в Process.
- `<title>` страницы приведён к формулировке с баннера: «Чистая речь — Анастасия,
  учитель-логопед».
- `ЛОГОТИП.webp` из пакета — младшая версия (1024px, без прозрачности) уже используемого лого,
  не заменяли (наш `logo.png` из `brand-v2/logo3.png` — источник выше по разрешению).
